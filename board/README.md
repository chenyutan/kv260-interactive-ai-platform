# KV260 实板验证

## ROI、量化张量与 DPU 热图

2026 年 9 月 14 日，在加载团队 `bodyink-usb-pl` 固件的 KV260 上，对 1080p、720p、540p 三种 YUYV 录制输入各取六帧。每帧测试两个 ROI。程序先运行 CPU 参考前处理，再由 PL 完成采样、缩放和量化，最后将两路输入分别送入同一 DPU。旧固件冻结了对应输入和热图。

[36 组实板记录](roi-equivalence.json) 逐组列出分辨率、帧号、ROI、设备完成标志、硬件周期、输入张量比较、热图比较、输出边界哨兵和旧固件参考比较。每组均通过。每个张量为 196,608 字节，每个热图为 65,536 字节。[黄金热图和索引](../data/README.md) 使用相同的高度、帧号、ROI 三元组。

[单 ROI 流水线测量](pipeline-timings.json) 摘录三个固件/后端组合在 720p 和 1080p 的实板结果。相同新固件的 720p 录制回放中，CPU 路径每秒更新 43.98 次姿态，PL 路径为 47.21 次。记录含采样帧数、丢帧、均值和 P95，测量覆盖前处理、DPU 与 CPU 解码。

## ARM 热图解码

2026 年 10 月 2 日，KV260 使用既有热图对照原始 CPU 解码器与优化方案。[逐方案结果](decoder-comparison.json) 保留 5 个方案的均值、中位数、P95、样本数和库文件摘要。8 张已有热图重复 25 轮，另有 25 个常量、随机、并列峰等合成输入在 3 个定点位置下测试，共 275 次输出比较。前五轮热身结束后，每方案交错计时 160 次。部署的单线程 `neon1` 与基线输出逐字节一致，均值从 6.540 ms 降到 5.135 ms，P95 从 12.927 ms 降到 8.741 ms。这组实测只计 ARM 解码。

## 用公开样例上板

1. 使用 KV260 的配套 Linux 镜像、XRT 与团队视觉固件，先完成仓库首页的构建、固件安装和 ARM 运行库编译。按生产配置准备 UIO 权限与占用锁，在视觉服务释放设备后以具有 UIO/XRT 访问权限的板端账户运行。
2. 将本仓库的 `board`、`data` 保持在同一父目录，执行 `python3 board/check_pl.py --runtime /path/to/bodyink-live`。运行目录内应有 `pl_bridge`、`libpl_mmio.so` 与 `libroi_copy.so`，两份库按首页说明放在 `pl_bridge` 内。
3. 脚本把公开合成的 32×24 YUYV 输入传给产品 PL 适配器，检查带填充行和奇数起点的 17×13 ROI。成功时输出硬件计时和 196,608 个一致字节的摘要。该入口调用硬件并使用单个合成输入；36 组历史实测独立保存在上方文件中。

原历史测试入口为 `bodyink-live/pl_bridge/test_pl_board.py`，依赖原录制 RAW 帧和冻结参考包。公开数据另提供可复现的合成输入和原始黄金热图。
