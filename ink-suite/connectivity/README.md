# 设备与联网

应用顶部的“设备 / Wi‑Fi”，以及各体验内“显示与退出 → 设备与联网”进入同一个原生管理页。设备操作时暂停当前体验，保留画卷和对局；返回后通过体验菜单选择继续。摄像头缺失或识别数据停滞时仍禁止体感动作，不能用“保持未连接”绕过就绪检测。

Wi‑Fi 页搜索附近网络，选择名称，输入密码后连接；常见开放、WPA2 和 WPA3 个人网络均由 NetworkManager 处理。已成功连接的网络保存自动重连配置；也可输入隐藏网络名称。没有键盘时使用屏幕键盘；右手可停留选择标签页、网络和按钮。中文网络名称可直接从搜索结果选择。企业认证网络请使用系统网络设置。

启动先留 8 秒等待枚举，持续断开 2 秒后才提示“XX 未连接”。提示提供“重连”和“保持未连接”，后者在本次断开期间不重复弹窗。实际重新连接后恢复检查，下次断线仍提醒；设备状态始终显示真实状态。未联网或音响未连接不会阻止离线体验。摄像头缺失时可用鼠标或触摸操作管理页；相机恢复后右手菜单重新等待新数据。

网络搜索、认证和设备枚举在后台线程运行，不占绘画线程；重复连接请求被拒绝，关闭应用后不会执行尚未开始的连接操作。Wi‑Fi 操作只选择无线网卡和无线配置，保留以太网、SSH 和现有网络配置。摄像头重连不重启已经运行的识别服务；音响重连重新检查接收器，并通过现有带回执的子进程协议修复体验声音，不自动恢复对局。

## Cube 2 音响保活

主程序运行期间，`AudioKeepalive` 在独立线程维护一个 48 kHz、双声道、全零 PCM 的 PulseAudio 输出。返回菜单或暂停游戏时，这条输出继续运行。只有 ALSA 声卡经 sysfs 对应到 VID `2dc8` 且 USB 产品名称含 `Cube` 的设备，才能成为保活目标；仅凭 PulseAudio 显示名称或 PID 不会选择音响。音响拔出、重新枚举或音频服务暂时失败后，线程按间隔重新检查并建立输出。

保活流与场景音频、太鼓音乐时钟分别管理。它不修改默认音响、系统音量或静音设置，也不推进、暂停或重建游戏的音乐。`start()`、`retry()`、`set_enabled()`、`status()`、`close()` 都不在 GTK 线程导入 GStreamer、运行命令或等待管线停止。状态中的 `inventory` 是工作线程的缓存。

## 官方自动关机条件

2026-09-30 核查的[八位堂 Cube 2 官方说明书](https://download.8bitdo.com/Manual/Other/cube-speaker/Retro-Cube-2-Speaker-N.pdf)英文印刷第 4 页（PDF 第 6 页）规定：开机后 1 分钟未连接会自动关机；连接后 15 分钟无操作也会自动关机；有线连接期间不会自动关机。说明书未定义“无操作”是否包含持续发送全零音频，也未列出 2.4G 模式下关闭自动关机的设置。

同日核查的[官方固件说明](https://support.8bitdo.com/)列出了 Cube 2 的 v1.31 和 v1.19 更新内容，涉及升级、蓝牙、无线连接和充电电量报告，没有说明无线待机设置或零 PCM 的保活语义。程序不进行固件升级或试探未公开的 USB 命令。

## 已验证的行为与验收范围

独立静音探针已确认正确 Cube 输出从 `SUSPENDED` 转为 `RUNNING`，建立一条指向该输出的 `s16le 2ch 48000Hz` 流；关闭探针后仅删除自身音频流，默认输出、静音和音量保持不变。证据保存在 `diagnostics/connectivity-audio-20260930/report.json`。

界面显示“保活中”表示主机持续发送静音数据，防止 PulseAudio 因无输出而挂起；它不构成音响无线端仍开机的证明。2.4G 接收器的 USB 声卡可能在音响关机后继续存在，程序没有官方接口读取音响无线端电源状态。因此 `firmware_standby` 保持 `unverified`，短时探针也不用于宣称“永不休眠”。

无线端验收应在音响已开机且连接正常时开始，在不播放游戏音效、不按音响按键的情况下持续静音保活至少 16 分钟（建议 20 分钟），记录主机输出状态，并由现场人员确认音响仍处于连接状态。官方说明书用常亮白色状态灯表示成功的 2.4G 连接。记录须说明测试时长、音响供电方式以及现场结果；不需要开启摄像头或采集音频。若现场确认仍自动关机，可采用官方说明书明确保证的音响 USB 有线连接，或在核实制造商的无线设置后另行实现。当前策略始终发送零 PCM，没有加入音调或噪声。
