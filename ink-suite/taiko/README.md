# 鼓动山河

原生 GTK3/Cairo 太鼓音游，复用 KV260 当前 `/api/state` 的 COCO17 姿态。程序不打开摄像头、不请求图像、不运行另一套模型。

## 玩法

原创曲目《青岚鼓引》长 72 秒，100 BPM。优先播放 Suite `audio/assets/bgm_taiko.wav` 的琴笛重编版，来自 `audio/build_assets.py`，其来源和 WAV hash 记录于 Suite `audio/manifest.json`；旧 `taiko/audio` 只作为回退。没有商业歌曲、采样包或外部录音。

可选「轻鼓入门」57 鼓、「山河合奏」69 鼓和「雷鼓破阵」87 鼓。进阶谱面通过左右交替提高密度，同一只手的相邻目标至少相隔 1.2 秒，给手臂留出回抬时间；每档把四个原有稀疏鼓点改为拍掌，全部音符时刻与数量保持不变。左右两轨圆点提前 3 秒出现，到鼓心时下挥对应的手；红色左手，青色右手，金色连线为双手同时向下击鼓；两鼓之间的紫色掌形轨道要求双手在胸前向内合拢拍掌，不能用双手下挥替代。每次拍掌后重新分开再拍，无需保持起点。可以在胸前先上挥再下挥，不必每次抬到固定高度，也不必击打真实物体；原先抬到肩旁再下挥的动作仍可使用，慢抬后快挥同样有效。按身体肩宽归一化，不依赖衣服颜色或掌心模型。左右为参与者自身左右手，屏幕镜像对应。

实际界面默认「体感判定」：正中 Perfect 为 ±110 ms、好鼓 Good 为 ±220 ms，入拍 OK 为 ±350 ms；两只不同手的合击间隔最多220 ms。三档基础得分分别1000、650、350，均可延续连击；连击加成每十连击20、最高200。超出范围、挥错手或只有单手未凑齐合击不加分，每条音符只计分一次。

「严谨判定」保留旧版 Perfect ±110 ms、Good ±220 ms、合击120 ms。菜单内切换档位先确认重开当前曲段，不能回头改变已判定的分数。鼓谱难度和判定宽容度独立；`Game`/`Session` 的代码默认值仍为strict，实际界面显式采用relaxed。

- **蓄势与高潮**：Perfect 蓄势 +8、Good +5、OK +3、漏鼓 -24，蓄满 100 进入 4.8 秒「山河共鸣」。此时正常鼓点得分翻倍，不重复蓄势；暂停时高潮计时也停止。局部金色轨道提示高潮，不使用全屏闪光。
- **乐句挑战**：「交替应和」「双手合击」「山河收势」分别要求接住指定乐句内的目标鼓点，奖励 1200 / 1600 / 2400 分；漏掉相关鼓点就错失该奖励，不会提前结束整曲。空挥无法刷分。
- **精准反馈**：显示稍早／稍晚的毫秒差，±35 ms 内提示节拍正好。准确率按 `(Perfect + 0.65 × Good + 0.35 × OK) / 已判定鼓数` 计算；评级 S≥95%、A≥85%、B≥70%、C≥50%，其余 D，无判定时显示 `--`。严谨档没有OK；这是节奏成绩，不是视觉模型准确率。
- **动作与评分分别反馈**：每次通过有效性与去重检查的下挥都有鼓声、鼓面回弹和墨圈，空挥和合击第一只手也有反馈，但不因此加分。动画从收到动作时开始完整播放；评分仍按原动作观察时间修正，不扩大命中窗口。界面提示未对上鼓点或等待另一手，避免把无得分误当成未识别。
- **分段修习**：可独立练左右入门、交替合击、山河终章。非开篇段先播放四拍准备音乐；末尾留出传输和校准宽限，避免最后一鼓被提前结算。成绩按本段单独计算；练完可手势选择「重新开局」再练，不自动无限循环。
- **无鼠标设置**：右臂转两圈，菜单首页直接选择「延迟校准」。总是偏晚选择「总是偏晚」把判定提前25 ms；总是偏早则推后25 ms。也可明确选择推后100或150 ms的快捷值，或清零，范围±500 ms、默认0。负值把动作判定推后，正值提前；不移动音乐或谱面，也不重算之前的分数。顶部数字框在暂停时可输入值。「鼓谱与判定」内可选择难度／体感或严谨规则／分段练习。设置保留至当前体验退出，重新进入采用启动参数默认值。

结算显示彩色山水卷、准确率评级、最高连击、三种判定数量和挑战奖励。练习段与完整曲目的结算明确区分；低分也有完整结尾。

## 音画与生命周期

- 正常模式以 GStreamer **真实音频流 position** 为唯一音乐时钟；音符位置、倒计时与判分都读这一时钟。音频独立推进，GTK 帧率不驱动声音。
- 使用后端原始观察时间修正采集到推理的延迟，接受不超过 450 ms 的有效源样本；重发序列、时间不推进、换人、明确 ROI 断续、跳点及过期数据不会继续击鼓。
- Miss 结算额外等待 450 ms 的传输宽限；这不扩大 Perfect/Good 命中窗口。正向手动校准会相应延后结算。
- `--input-offset-ms` 范围 -500～500，正值把判分时刻前移。默认 0；菜单可在暂停时修改，改偏移不会 seek 或篡改已经得到的分数。实际声卡、屏幕和体感的端到端延迟尚需真人校准，静音管线结果不能代替音响实测。
- 人体存在与单腕可击鼓分开判定。短暂缺腕/缺肩不暂停歌曲，也不补坐标或跨失点补造击鼓；持续无人超过1秒或有效源观测停更超过650毫秒才暂停。恢复依赖约180毫秒的新身体观测，恢复前的旧姿态不能补发。
- 运动连续性按原始相邻观测间隔判断，界面重复绘制不清空仍有效的轨迹。恢复前的新鲜观测可证明摄像头及身体存在，但不能蓄势或击鼓；恢复窗口由新身体观测推进，不被缓存刷新重新计时。
- 画圈候选 `control_active` 立即停止击鼓并清蓄势，但不会因此暂停整曲；真正打开菜单或宿主暂停立即冻结音乐和判分。源时间戳水位跨失点保存，乱序、重发与过期包不能补造第二击。
- 音频断开、报错或时钟停止推进时冻结；「重试音频」在当前曲目位置重新打开设备，「无声练习」是用户明确选择的独立无声时钟，界面始终标注无声。重新开始会重置分数并 seek 到当前曲段起点；seek 失败不冒充开始成功。重复暂停不重复操作 GStreamer 管线。
- stdout JSON 协议：ready / paused / resumed / shutdown / fullscreen_requested / menu_requested；pause/resume 带 game_state、game_clock。XEmbed 子进程读取 stdin 的 pause/resume/shutdown，EOF 退出。

## 启动与验证

在 Suite 根目录：

```sh
python3 taiko/main.py --pose-url http://127.0.0.1:8088/api/state --fullscreen
python3 taiko/main.py --judgment strict --input-offset-ms -100 --fullscreen
python3 taiko/main.py --offline-preview --autoplay --audio-sink fakesink --quit-after 78 --metrics /tmp/taiko-metrics.json
python3 taiko/main.py --offline-preview --difficulty hard --practice alternate --audio-sink fakesink
python3 -m unittest taiko.test_engine taiko.test_gameplay taiko.test_playability taiko.test_input taiko.test_panel taiko.test_renderer -v
```

`--offline-preview` 默认 fakesink，绝不默认发出扬声器声音；F 左、J 右、K 拍掌、空格双鼓可检查键盘判分。`--autoplay` 是明确的合成验收选项，只有离线模式可启用，正常玩法没有自动命中。

私有 GTK/GStreamer 烟测，不访问共享接口：

```sh
PATH=/home/ubuntu/connected-gallery-network/xvfb-standalone/root/usr/bin:"$PATH" \
GDK_BACKEND=x11 GDK_RENDERING=image xvfb-run -a -s '-screen 0 1024x600x16 -nolisten tcp' \
python3 taiko/verify_native.py --output /tmp/taiko-evidence --seconds 12
```

诊断只记录状态、时钟、得分和绘制耗时；截图来自合成渲染，未录摄像头。`draw_callback_fps` 是 GTK 实际绘制回调速率，不是光学显示刷新率。

常规运行也会异步保留最新计数到 `$XDG_RUNTIME_DIR/ink-suite-taiko-<uid>.json`，使用RAM和单个待写快照；必须用其中的PID、启动时间确认进程身份。包含真实源帧率、手腕可见次数、拒击原因、暂停/恢复原因与歌曲位置。`--metrics` 可指定验收目录。退出最终快照不保证落盘，不把旧文件当作新一轮验收。

输入诊断最多保留64个事件，记录原观察时间、接收时龄、动作路径、评分时刻及最近鼓点差值。每手还区分已经消费过的同一下挥、未重新蓄势、跳点等拒绝原因；这些记录不会补造动作或改分。重开一局时分数和动画清零，诊断计数保留至当前进程退出。

## 依赖与范围

运行依赖 Python3、GTK3/PyGObject、Cairo、GStreamer playbin/WAV 解码与音频输出。复用 Suite 的 `sword.rgb565`、`sword.metrics` 与可选 `sword.alpha_blit`；NEON 库不可用时自动用等价 Cairo。NumPy 仅重建原创 WAV 时需要，日常运行不需要。

文字缓存最多 256 项；源谱面只有整曲固定数量，反馈最多 12 条，已消费事件去重最多 512 项；窗口尺寸变化才重建背景/鼓缓存。画面保留全部音符和效果，不以删谱面换性能。当前不含在线音乐库、自定义上传歌曲、商业歌曲或真人录音。

## 2026-10-01 中央拍掌与分级特效

中央拍掌复用现有肩腕点，双腕距离穿过接触代理线、两只手确实向内移动时产生单个 C 事件；它不能证明掌心物理接触。原始时间戳、450 ms 击打时龄、暂停恢复 epoch、去重和独立音乐连续性全部保留。初始合掌静止、双手下挥、单手横扫、遮挡或过期姿态不会补造拍掌。

Perfect 使用金朱色云纹、莲瓣与墨滴，Good 使用青色涟漪与墨滴，OK 使用克制的细墨圈；双鼓效果只在左右鼓出现，拍掌效果位于中央。等级动画沿接收显示时刻播放，不因推理迟到缩短。初版等级效果预先缓存为64块局部透明图，仅尺寸变化时重建，运行中不做全屏模糊。

本次验证证据在 Suite diagnostics/taiko-clap-20261001；WSL 美术预览在工程根目录 diagnostics/taiko-clap-render-20261001。真人胸前拍掌成功率需要单独验收，合成姿态通过不等同于真人验收。

## 2026-10-01 真人反馈后的拍掌与特效加强

拍掌开手代理距离从1.00降至0.80、接触代理线从0.62放宽至0.75肩宽；保留周期内最宽起点，允许两手错峰合拢。仍需至少0.18累计收敛和每手0.05真实及相对向内运动，450毫秒时龄、240毫秒相邻源间隔及850毫秒周期不变。接触线会随小开幅降低，以避免轻微抖动触发。

Perfect为1.08秒金朱重墨莲爆，Good为0.74秒青墨双斩，OK为0.46秒墨点。71块缓存在1024×471占9.25MiB；音符置顶，大特效局部裁剪保护HUD，不做全屏闪黑闪白。板端离屏绘制须单独验证，WSL预览不能代表A53性能。

一次真人曲目中的约0.84秒暂停来自ROI切换。音乐仅对已知ROI后备切换、同来源身份、240毫秒内四个有效肩髋锚点近邻连续时保留；源/身份改变、显式重置、身体跳变、乱序和过期仍按原规则暂停。击鼓/拍掌运动史继续严格重置，不跨ROI切换补造命中。本轮首次切换缺紧邻前帧坐标，不能宣称对它完成精确重放；第二次切换的两个实测端点用于回归。

证据：Suite diagnostics/taiko-clap-refine-20261001；美术对比：工程根目录 diagnostics/taiko-fx-boost-20261001。真人复测需另行确认。

拍掌准备阶段仅在每手向内运动足够明显、不是以向下敲鼓为主时抑制L/R；实际跨接触线仍优先C。完全相同的“下挥且稍收拢”前缀无法预知接下来是否会拍掌，现选择保留这类下挥响应而不加等待，后续真实穿越线才产生C；不保证此歧义轨迹在接触前完全无鼓声。
